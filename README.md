# Snitch — screenshot the trick. We’ll name it and report it.

Snitch is a consumer watchdog for **dark patterns** on Indian shopping, travel and subscription apps.
You upload a screenshot; a vision model reads it **live**, names each dark pattern, cites the item in
India’s *Guidelines for Prevention and Regulation of Dark Patterns, 2023* (CCPA), drafts a grievance
for the National Consumer Helpline, and exports a share card.

**Nothing in the UI is hardcoded.** Every finding, every complaint and every share card is generated from
the screenshot you upload, at the moment you upload it. The only static data in the repo is the reference
list of the 13 patterns (`src/data/patterns.ts`) and three illustrative *input* screenshots
(`public/samples/`) — their results still come from the model each time.

## How it works

```
Screenshot (phone/browser)
   └─► src/lib/image.ts   downscale to ≤1568px, JPEG, SHA-256 id
        └─► POST /api/analyze  (Vercel Function, key stays on server)
             └─► Gemini vision · JSON schema · 13-pattern rulebook
                  └─► findings: pattern · Annexure item · evidence · explanation · confidence · box
                       ├─► Analysis screen: numbered pins on your screenshot + cards
                       ├─► POST /api/grievance → complaint text (editable, you send it)
                       └─► Share card drawn on <canvas> (privacy mode blurs everything but the evidence)
```

## Run locally

```bash
npm install
cp .env.example .env         # paste your Gemini key from https://aistudio.google.com/apikey
npm run dev                  # http://localhost:3000  — /api/* is served by the Vite dev middleware
```

## Deploy on Vercel

1. Push the repo and import it in Vercel (framework: Vite — auto-detected).
2. **Project → Settings → Environment Variables →** add `GEMINI_API_KEY` (Production + Preview).
   Optional: `GEMINI_MODEL` (default `gemini-2.5-flash`).
3. Redeploy. The functions in `api/` run on Node.js with a 60s limit (`vercel.json`).
4. Open `/api/health` — it should return `"configured": true`.

## Project layout

```
server/
  gemini.ts             shared server logic: prompts, JSON schemas, validation (imported by api/*)
api/
  analyze.ts            POST /api/analyze   → live analysis of one screenshot
  grievance.ts          POST /api/grievance → live complaint draft from the findings
  health.ts             GET  /api/health    → is the server configured?
src/
  App.tsx               state machine: idle → analyzing → done | error; responsive shell
  components/
    ScanScreen.tsx      drop / paste / choose / samples / recent real scans
    AnalysisScreen.tsx  live progress, pins from bounding boxes, finding cards, states
    GrievanceScreen.tsx empty form (never pre-filled), live draft, review gate, copy, portal link
    ShareDossierScreen.tsx  canvas share card, privacy blur, download / native share
    PatternsScreen.tsx  reference: the 13 patterns
    Header.tsx / BottomNav.tsx  phone+tablet chrome; Sidebar for desktop
  lib/
    api.ts              fetch client, mapping, template fallback for drafting
    image.ts            downscale / hash / read helpers
    storage.ts          on-device cache of REAL results (localStorage)
    theme.ts            colour tokens for dark + light
public/samples/         three illustrative input screenshots (generated by scripts/make-samples.py)
```

## Responsive behaviour

* `< 640px` phones: fixed header + bottom tab bar, single column, 44px touch targets, 16px inputs.
* `640–1023px` tablets: wider column, tab labels beside icons.
* `≥ 1024px` desktop: left sidebar replaces header and tab bar; Scan, Analysis, Grievance and Share
  become two-pane layouts (screenshot sticky on the left, content on the right).
* Honors `prefers-reduced-motion` and `prefers-color-scheme` (first visit), visible keyboard focus.

## Honesty guardrails

* Every finding shows the model’s **confidence** and the **on-screen evidence** it used.
* Snitch **never submits** anything — you review, copy and file yourself (1915 / consumerhelpline.gov.in).
* Not legal advice. Citations use “Guideline 4 read with Annexure 1, Item N” of the 2023 Guidelines.
* Screenshots are analysed and not stored on the server; the API key never reaches the browser.
